# 多环境配置管理说明

## 概述

本项目支持开发、测试、生产三种环境的配置管理，通过环境变量和配置文件实现灵活的环境切换。

## 环境说明

| 环境 | 配置文件 | 用途 |
|------|---------|------|
| development | application-dev.yml | 本地开发调试 |
| test | application-test.yml | 测试环境部署 |
| production | application-prod.yml | 生产环境部署 |

## 后端配置

### 配置文件结构

```
backend/src/main/resources/
├── application.yml          # 主配置文件
├── application-dev.yml      # 开发环境配置
├── application-test.yml     # 测试环境配置
└── application-prod.yml     # 生产环境配置
```

### 环境切换方式

#### 1. Maven Profile 方式

```bash
# 开发环境（默认）
mvn spring-boot:run

# 测试环境
mvn spring-boot:run -Ptest

# 生产环境
mvn spring-boot:run -Pprod

# 打包时指定环境
mvn clean package -Pprod
```

#### 2. 环境变量方式

```bash
# 设置环境变量
export SPRING_PROFILES_ACTIVE=prod

# 或在启动时指定
java -jar app.jar --spring.profiles.active=prod
```

#### 3. Docker 环境变量

```yaml
# docker-compose.yml
environment:
  SPRING_PROFILES_ACTIVE: prod
```

### 环境配置差异

| 配置项 | 开发环境 | 测试环境 | 生产环境 |
|--------|---------|---------|---------|
| 数据库 | localhost:3306 | localhost:3306 | mysql:3306 |
| Redis | localhost:6379 | localhost:6379 | redis:6379 |
| 日志级别 | DEBUG | DEBUG | INFO |
| Swagger | 启用 | 启用 | 禁用 |
| 连接池大小 | 10 | 15 | 30 |
| 日志保留 | 7天 | 14天 | 30天 |

### 敏感配置管理

生产环境敏感配置通过环境变量注入：

```yaml
# application-prod.yml
spring:
  datasource:
    password: ${DB_PASSWORD}  # 从环境变量读取
jwt:
  secret: ${JWT_SECRET}       # 从环境变量读取
```

## 前端配置

### 配置文件结构

```
frontend/
├── .env.development    # 开发环境
├── .env.test          # 测试环境
└── .env.production    # 生产环境
```

### 环境变量格式

```bash
# .env.development
VITE_API_BASE_URL=/api
VITE_APP_TITLE=Ticket System - Development
VITE_APP_ENV=development

# .env.test
VITE_API_BASE_URL=/api
VITE_APP_TITLE=Ticket System - Test
VITE_APP_ENV=test

# .env.production
VITE_API_BASE_URL=/api
VITE_APP_TITLE=Ticket System
VITE_APP_ENV=production
```

### 环境切换方式

```bash
# 开发环境
npm run dev              # 自动加载 .env.development

# 构建测试环境
npm run build:test       # 自动加载 .env.test

# 构建生产环境
npm run build:prod       # 自动加载 .env.production
```

### 在代码中使用环境变量

```javascript
// 获取 API 基础地址
const apiUrl = import.meta.env.VITE_API_BASE_URL

// 获取应用标题
const title = import.meta.env.VITE_APP_TITLE

// 判断当前环境
if (import.meta.env.VITE_APP_ENV === 'production') {
  // 生产环境逻辑
}
```

## 配置最佳实践

### 1. 敏感信息管理

- 不要将敏感信息（密码、密钥）提交到版本控制
- 使用环境变量或密钥管理服务
- 生产环境必须使用强密码

### 2. 配置优先级

配置加载优先级（从高到低）：
1. 命令行参数
2. 环境变量
3. application-{profile}.yml
4. application.yml

### 3. 环境隔离

- 不同环境使用不同的数据库
- 测试环境使用独立的 Redis 数据库
- 生产环境禁用调试功能

### 4. 日志配置

| 环境 | 级别 | 输出位置 | 保留时间 |
|------|------|---------|---------|
| 开发 | DEBUG | 控制台 + 文件 | 7天 |
| 测试 | DEBUG | 文件 | 14天 |
| 生产 | INFO | 文件 | 30天 |

## 常见问题

### Q: 如何验证当前环境？

**后端：**
```bash
# 查看日志
curl http://localhost:8080/api/actuator/env | grep active
```

**前端：**
```javascript
console.log(import.meta.env.VITE_APP_ENV)
```

### Q: 如何添加新的环境配置？

1. 创建配置文件 `application-{env}.yml`
2. 在 `pom.xml` 添加 Profile
3. 创建对应的环境变量文件

### Q: 如何覆盖配置？

```bash
# 通过环境变量覆盖
export DB_HOST=new-host
export DB_PORT=3307

# 通过命令行参数覆盖
java -jar app.jar --spring.datasource.url=jdbc:mysql://new-host:3306/db
```
