## 概述

本项目支持三种运行环境：

| 环境 | 说明 | 主要用途 |
|------|------|----------|
| **dev** (开发环境) | 调试模式开启，日志级别 DEBUG | 本地开发、功能调试 |
| **test** (测试环境) | 部分调试功能开启，日志级别 INFO | 集成测试、QA验证 |
| **prod** (生产环境) | 调试模式关闭，安全配置启用 | 正式部署、生产运行 |

## 后端环境配置

### 配置文件结构

```
backend/src/main/resources/
├── application.yml          # 主配置文件
├── application-dev.yml      # 开发环境配置
├── application-test.yml     # 测试环境配置
└── application-prod.yml     # 生产环境配置
```

### 各环境配置详情

#### 1. 开发环境 (application-dev.yml)

**核心配置：**
- **数据库连接**：本地 MySQL，密码简单
- **Redis**：本地实例，无密码
- **日志级别**：DEBUG，输出详细 SQL
- **Swagger**：完全启用
- **Actuator**：所有端点暴露

```yaml
# 开发环境关键配置
logging:
  level:
    com.ticket: debug
    com.ticket.mapper: debug

springdoc:
  swagger-ui:
    enabled: true

management:
  endpoints:
    web:
      exposure:
        include: "*"
```

#### 2. 测试环境 (application-test.yml)

**核心配置：**
- **数据库连接**：测试数据库实例
- **Redis**：测试环境 Redis（DB 1）
- **日志级别**：INFO，记录关键操作
- **Swagger**：启用供测试人员查看
- **Actuator**：仅暴露健康检查和指标

```yaml
# 测试环境关键配置
spring:
  datasource:
    url: jdbc:mysql://.../ticket_system_test
  data:
    redis:
      database: 1

logging:
  level:
    com.ticket: info
  file:
    max-history: 15
```

#### 3. 生产环境 (application-prod.yml)

**核心配置：**
- **数据库连接**：生产数据库，强制 SSL
- **Redis**：生产环境，强制密码验证
- **日志级别**：WARN，仅记录异常和错误
- **Swagger**：完全禁用
- **Actuator**：仅暴露基本健康检查
- **JWT**：强制使用环境变量密钥

```yaml
# 生产环境关键配置
spring:
  datasource:
    url: jdbc:mysql://...?useSSL=true
    hikari:
      maximum-pool-size: 50

springdoc:
  swagger-ui:
    enabled: false
  api-docs:
    enabled: false

management:
  endpoints:
    web:
      exposure:
        include: health,info
```

### Maven 多环境打包

#### Profile 配置

```xml
<profiles>
  <profile>
    <id>dev</id>
    <activation>
      <activeByDefault>true</activeByDefault>
    </activation>
    <properties>
      <spring.profiles.active>dev</spring.profiles.active>
    </properties>
  </profile>
  <profile>
    <id>test</id>
    <properties>
      <spring.profiles.active>test</spring.profiles.active>
    </properties>
  </profile>
  <profile>
    <id>prod</id>
    <properties>
      <spring.profiles.active>prod</spring.profiles.active>
    </properties>
  </profile>
</profiles>
```

#### 打包命令

```bash
# 开发环境（默认）
mvn clean package

# 指定测试环境
mvn clean package -Ptest

# 指定生产环境
mvn clean package -Pprod

# 跳过测试
mvn clean package -Pprod -DskipTests
```

VITE_ENABLE_MOCK=false
VITE_ENABLE_DEVTOOLS=true

#### 2. 测试环境 (.env.test)

```env
VITE_APP_TITLE=工单系统 - 测试环境
VITE_APP_ENV=test
VITE_API_BASE_URL=/api
VITE_API_TIMEOUT=30000
VITE_ENABLE_MOCK=false
VITE_ENABLE_DEVTOOLS=false
```

#### 3. 生产环境 (.env.production)

```env
VITE_APP_TITLE=工单系统
VITE_APP_ENV=production
VITE_API_BASE_URL=/api
VITE_API_TIMEOUT=60000
VITE_ENABLE_MOCK=false
VITE_ENABLE_DEVTOOLS=false
```

### Vite 多环境构建

#### 构建命令

```bash
# 开发模式（启动本地服务器）
npm run dev              # 开发环境
npm run dev:test         # 测试环境
npm run dev:prod         # 生产环境

# 构建生产包
npm run build            # 生产环境（默认）
npm run build:dev        # 开发环境构建
npm run build:test       # 测试环境构建
npm run build:prod       # 生产环境构建
```

#### 在代码中使用环境变量

```javascript
// 获取当前环境
const env = import.meta.env.VITE_APP_ENV

// 根据环境配置不同逻辑
if (import.meta.env.DEV) {
  // 仅开发环境执行
  console.log('Running in development mode')
}

if (import.meta.env.PROD) {
  // 仅生产环境执行
  console.log('Running in production mode')
}

// API 基础地址
const API_BASE_URL = import.meta.env.VITE_API_BASE_URL
```

## 环境切换指南

### 本地开发环境切换

#### 后端切换方式

**方式一：修改主配置文件**

```yaml
# application.yml
spring:
  profiles:
    active: dev  # 切换为 dev/test/prod
```

**方式二：IDEA 运行参数**

```
# VM options
-Dspring.profiles.active=dev

# Program arguments
--spring.profiles.active=dev
```

**方式三：环境变量**

```bash
# Linux/macOS
export SPRING_PROFILES_ACTIVE=dev

# Windows
set SPRING_PROFILES_ACTIVE=dev
```

#### 前端切换方式

直接使用对应的 npm 脚本：

```bash
npm run dev        # 开发环境
npm run dev:test   # 测试环境
npm run dev:prod   # 生产环境
```

### Docker 环境切换

#### 方式一：环境变量

```bash
# 启动时指定环境
SPRING_PROFILES_ACTIVE=test docker compose up -d

# 或使用 Makefile
make up-dev
```

#### 方式二：.env 文件

在项目根目录创建 `.env` 文件：

```env
SPRING_PROFILES_ACTIVE=prod
DB_PASSWORD=your_prod_password
JWT_SECRET=your_prod_jwt_secret
```

#### 方式三：修改 docker-compose.yml

```yaml
services:
  backend:
    environment:
      SPRING_PROFILES_ACTIVE: prod
```

## 最佳实践

### 1. 配置文件管理原则

- **主配置文件** `application.yml`：存放所有环境通用配置
- **环境配置文件**：仅存放该环境差异化配置
- **敏感信息**：生产环境必须使用环境变量，禁止硬编码

### 2. 敏感信息处理

**错误做法：**
```yaml
# ❌ 禁止在配置文件中明文写密码
jwt:
  secret: my-super-secret-key
```

**正确做法：**
```yaml
# ✅ 使用环境变量注入
jwt:
  secret: ${JWT_SECRET}
```

启动时传入：
```bash
JWT_SECRET=your-actual-secret java -jar app.jar
```

### 3. 新增配置项规范

新增配置项时：
1. 在 `application.yml` 中定义默认值
2. 如各环境有差异，在对应环境配置中覆盖
3. 生产环境敏感配置必须使用环境变量

### 4. 环境验证

启动后验证当前环境：

**后端验证：**
```bash
# 查看健康检查端点
curl http://localhost:8080/api/actuator/env | grep activeProfiles
```

**前端验证：**
```javascript
// 浏览器控制台
console.log(import.meta.env.VITE_APP_ENV)
```

### 5. CI/CD 环境

GitHub Actions 流水线中：
- 测试阶段自动使用 `test` profile
- 构建生产镜像时使用 `prod` profile
- 所有敏感信息通过 GitHub Secrets 注入

## 故障排查

### 问题 1：环境切换不生效

**可能原因：**
- IDE 缓存未清理
- 配置文件格式错误
- 启动参数优先级高于配置文件

**解决方案：**
```bash
# 清理并重新构建
mvn clean
mvn compile

# 检查启动参数优先级
# 优先级从高到低：
# 1. 命令行参数
# 2. JVM系统属性
# 3. 操作系统环境变量
# 4. 配置文件
```

### 问题 2：前端环境变量不生效

**可能原因：**
- 变量名未以 `VITE_` 开头
- 修改后未重启 dev server
- 变量类型不匹配

**解决方案：**
```bash
# 停止服务后重新启动
npm run dev
```

## 总结

- 开发环境追求**开发效率**，调试信息全面
- 测试环境追求**稳定可控**，模拟生产行为
- 生产环境追求**安全性能**，最小权限原则
- 所有环境切换都有明确、可复现的操作方式
- 敏感信息永不提交到代码仓库
