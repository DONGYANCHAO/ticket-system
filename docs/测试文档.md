## 测试概述

### 测试策略

工单系统采用分层测试策略：

```
┌─────────────────────────────────────┐
│         端到端测试 (E2E)             │
├─────────────────────────────────────┤
│         集成测试 (Integration)       │
├─────────────────────────────────────┤
│         单元测试 (Unit)              │
└─────────────────────────────────────┘
```

### 测试技术栈

| 层级 | 后端 | 前端 |
|------|------|------|
| 单元测试 | JUnit 5 + Mockito | Vitest + Vue Test Utils |
| 集成测试 | Spring Boot Test | - |
| 覆盖率 | JaCoCo | v8 |
| 断言库 | AssertJ | Chai |
| Mock | Mockito | vi.fn() |

### 单元测试

#### 1. 服务层测试（Mockito）

```java
@ExtendWith(MockitoExtension.class)
@DisplayName("工单服务测试")
class TicketServiceTest {

    @Mock
    private TicketMapper ticketMapper;

    @InjectMocks
    private TicketServiceImpl ticketService;

    @Test
    @DisplayName("创建工单 - 成功")
    void createTicket_Success() {
        // given
        when(ticketMapper.insert(any(Ticket.class))).thenReturn(1);

        // when
        Map<String, Object> result = ticketService.createTicket(createRequest);

        // then
        assertNotNull(result);
        verify(ticketMapper, times(1)).insert(any(Ticket.class));
    }
}
```

#### 2. 运行单元测试

```bash
# 运行所有单元测试
mvn clean test

# 运行特定测试类
mvn test -Dtest=TicketServiceTest

# 运行特定测试方法
mvn test -Dtest=TicketServiceTest#createTicket_Success
```

### 集成测试

#### 1. Controller 层测试（Spring Boot Test）

```java
@SpringBootTest
@AutoConfigureMockMvc
@ActiveProfiles("test")
@Transactional
class TicketControllerIntegrationTest {

    @Autowired
    private MockMvc mockMvc;

    @Test
    @WithMockUser(username = "admin", roles = {"ADMIN"})
    @DisplayName("创建工单 - 成功")
    void createTicket_Success() throws Exception {
        mockMvc.perform(post("/api/ticket")
                        .contentType(MediaType.APPLICATION_JSON)
                        .content(objectMapper.writeValueAsString(createRequest)))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.code").value(200));
    }
}
```

## CI/CD 集成

### GitHub Actions 工作流

```yaml
name: CI/CD Pipeline

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main, develop ]

jobs:
  backend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          java-version: '17'
          distribution: 'temurin'
      - run: mvn clean test -Ptest
      - uses: codecov/codecov-action@v4
        with:
          files: backend/target/site/jacoco/jacoco.xml
          flags: backend

  frontend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '18'
      - run: npm ci
      - run: npm run test:coverage
      - uses: codecov/codecov-action@v4
        with:
          files: frontend/coverage/lcov.info
          flags: frontend
```

## 测试最佳实践

### 命名规范

1. **测试类名**：`被测试类名 + Test/IntegrationTest`
   - 例：`TicketServiceTest`, `TicketControllerIntegrationTest`

2. **测试方法名**：`被测试方法名_场景_预期结果`
   - 例：`createTicket_Success`, `updateTicket_NotFound`

3. **DisplayName**：使用中文描述测试目的
   - 例：`@DisplayName("创建工单 - 成功")`

### 测试结构（AAA）

```java
@Test
void createTicket_Success() {
    // Arrange (准备)
    when(ticketMapper.insert(any())).thenReturn(1);

    // Act (执行)
    Map<String, Object> result = ticketService.createTicket(request);

    // Assert (断言)
    assertNotNull(result);
    verify(ticketMapper).insert(any());
}
```

### 测试数据管理

1. **使用 @BeforeEach 准备测试数据**
2. **使用 @AfterEach 清理测试数据**
3. **使用 @Transactional 自动回滚数据库操作**

### Mock 最佳实践

1. **只 Mock 外部依赖**（数据库、第三方服务）
2. **不要 Mock 被测试类本身**
3. **验证 Mock 对象的交互**

```java
// 好的做法
verify(ticketMapper, times(1)).insert(any(Ticket.class));

// 避免过度验证
verify(ticketMapper).insert(any());  // 推荐
verify(ticketMapper).insert(argThat(ticket -> ticket.getTitle().equals("test")));  // 过度验证
```

### 测试隔离

1. **每个测试应该是独立的**
2. **不要依赖测试执行顺序**
3. **使用 @DirtiesContext 在需要时重置 Spring 上下文**

## 常见问题

### Q: 测试运行很慢怎么办？

**A:**
1. 使用 H2 内存数据库代替真实数据库
2. 使用 @MockBean 代替真实依赖
3. 并行运行测试：`mvn test -T 4`

### Q: 如何处理异步代码测试？

**A:**
```java
// 后端
awaitility.await()
    .atMost(Duration.ofSeconds(5))
    .untilAsserted(() -> {
        assertEquals(expected, actual);
    });

// 前端
await flushPromises()
expect(wrapper.text()).toContain('loaded')
```

### Q: 如何测试私有方法？

**A:**
1. **不要直接测试私有方法**，通过公有方法间接测试
2. 如果必须测试，考虑重构代码
3. 使用反射（不推荐）
